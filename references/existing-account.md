# 模式 A：已有账号新增站点/店铺

## 识别目标，避免串店

登录后读取商户名称/ID、现有店铺列表、目标域名、环境标识及审核状态。相同品牌或域名已有店铺时先核实是否复用；用户明确要求独立店铺则创建对应新店，不擅自合并。用目标 storeId 标识后续资源，不能仅凭左上角品牌名。

## 创建和补齐店铺

1. 在实际后台定位“店铺/Store”，填写真实品牌名、正式网站、客服邮箱、产品说明和官方 Logo。品牌名与网址是两个字段，不互相替代。
2. 完成当次要求的域名/邮箱验证。DNS 或验证文件先准备准确记录，按现有授权修改，再验证解析和站点路由；不覆盖已有 DNS。需要用户收验证码时先填完其他字段。
3. 逐项检查店铺审核、业务信息、条款/政策要求；缺项补齐。保留新店铺的独立审核状态，不能套用老店“已通过”截图。
4. 核对币种、付款方式、账单品牌等实际可用项。支付方式可用性受账号、地区、币种和商品类型影响，按官方当前规则实测。
5. 结算设置：区分收款渠道与商户结算账户。读取现有已验证账户，只在用户确认适用于新店时关联；新增/更换账户使用真实主体与资料。不要发起提现或测试转账。
6. 通知：核对买家收据、续费提醒、商户订单/退款/争议通知及收件地址。按业务需要开启，避免把其他店铺通知发送到本店客户或错误邮箱；不机械复制固定数量的开关。
7. 保存后重新进入店铺页，核对品牌、域名、邮箱、Logo、结算账户掩码、通知及正式权限。

## 商品与集成

进入 [共用配置](integration.md)。商品必须归属新店和正确环境；账户级密钥是否有跨店权限以当次后台为准，优先最小必要权限。新站复用同一商户不等于复用上一站的商品/通知地址。

若新店仍在审核：继续测试接入，报告“店铺正式权限待审核”，不得声称可正式收款。
