# 模式 B：从注册开始

## 注册前

确认用户要申请的实际经营主体、运营地区、联系邮箱、网站及收费模型。查看当次 Waffo 官方入口、可服务地区、主体条件和要求，不承诺必定通过或固定审核时间。使用官方入口进入注册，不通过搜索广告输入身份或密钥。

核对网站能公开访问，有真实产品展示、可理解的价格和交付方式、客服联系方式，以及符合实际业务的服务条款、隐私政策、退款/取消政策。若缺页面，先在当前项目编写真实内容并按授权部署；不得复制别站主体或虚构合规承诺。

## 注册与验证

1. 读取注册页全部字段和实际条款，使用用户提供的邮箱/主体信息。已有账号先登录，不重复注册。
2. 密码由用户输入或使用获授权的安全密码管理能力，不在聊天中索取明文密码。
3. 填写可确认的字段后，让用户完成邮箱验证、验证码或二次验证。保留所在页面和下一步，不尝试绕过。
4. 记录账号已验证状态；“可登录”不代表“商户获批”。

## 商户申请

1. 逐项整理当前页面实际要求：主体类型、法定名称、地址、注册信息、负责人/受益人、经营内容、域名、客户地区、交易模式及结算资料。不是每种主体都需要相同材料，不照搬一份固定清单。
2. 仅用用户确认的真实材料填写；身份证、税号、银行资料经安全界面处理，报告只写“已填写/待提供”和掩码。
3. 审阅申请摘要、平台要求的声明和合同；须用户亲自确认的真实性、签署或身份认证交给用户。常规资料填写与页面整理继续完成。
4. 提交已获授权的申请，核实成功提示与后台申请状态，记录提交时间、需要补充的项目。不要反复提交未知结果的申请。
5. 待审核时可完成测试模式接入、商品草案及网站后台代码。未获正式权限时不伪装为正式可收款。
6. 审核拒绝或补件：准确摘录原因，修复对应事实/页面并补件；不换主体信息逃避审核。用户未要求持续监控时，不自建自动任务。

## 获批后的汇合点

重新读取商户、目标店铺和正式环境各自的状态。商户获批不保证新店铺/域名自动获批。进入 [模式 A](existing-account.md)，按实际后台需要新建或补齐首个店铺，再执行共用后台接入和验收。
